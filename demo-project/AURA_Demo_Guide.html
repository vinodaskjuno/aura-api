Demo: Dev Workspace

🎯
What to show AURA understands the full InsCore Payment Platform from source code — without anyone manually documenting it. It builds a live knowledge graph connecting code, services, infrastructure, databases, and dependencies.
1

Navigate to Dev Workspace

Click Dev Workspace in the left sidebar. You'll see sample projects already loaded, including the InsCore Payment Platform (LOCAL DEMO).

💡 The "SAMPLE" purple badge indicates pre-loaded demo projects. The LOCAL DEMO points to real local Python code.
2

Open InsCore Payment Platform

Click on the project card. The Overview tab shows tech stack detected, repositories connected, and service relationships discovered.

💡 Point out: 13 classes, 12 service methods, 786 lines of Python code — all discovered automatically from local files.
3

Click "Re-Analyse" to run live analysis

This triggers CodeAnalysisAgent → ReverseEngineeringAgent → KnowledgeGraphAgent in sequence. Each agent runs, logs activity, and updates the knowledge graph.

💡 Show the Activity tab updating in real time as agents complete.
4

Ontology Graph — hover & expand

Switch to the Ontology Graph tab.
• Hover any node → all connected nodes glow, unrelated nodes dim
• Click any node → expand children, see relationships in the detail panel
• Use the Depth selector (1/2/3/All) to control graph depth

💡 Demo: hover PaymentService → shows it connects to payment_db, UserService, AuditService, EKS-prod-cluster, and AWS Lambda.
5

Mind Map — project hierarchy

Switch to Mind Map tab. Shows the project as a tree: Services → APIs → Infra → Tech Stack → Databases. Fully draggable.

6

Knowledge Diagram — relationships

Switch to Knowledge Diagram tab. Shows typed entity nodes (Application, Service, API, Database, Infrastructure, Vulnerability) with labeled edge relationships.

💡 Point out: this is the ontology schema diagram — Application → contains → Service → deployed_on → Kubernetes. Zero manual documentation needed.
7

Create a new project (optional live demo)

Click New Project → enter a name → add repos as either Git URL or Local Path using the toggle on each repo row → click Create & Analyse.

💡 Show both Git URL and Local Path modes in the same project for different repo types (e.g., UI from GitHub, legacy backend from local path).
"Traditional documentation takes weeks and becomes outdated immediately. AURA builds the living documentation automatically, from the code itself, and keeps it current every time analysis runs."

Demo: QA / Testing Workspace

🎯
What to show AURA generates a complete test suite automatically from the knowledge graph — Playwright UI tests, API tests, integration tests, regression tests, negative cases, and boundary conditions. No test engineer needs to write tests from scratch.
1

Navigate to QA / Testing

Click QA / Testing in the sidebar. Select InsCore Payment Service from the project dropdown. You'll see existing test suites if any have been generated.

2

Click "Generate Tests"

The modal shows 6 test type checkboxes — all enabled by default:

◈ Playwright UI — browser end-to-end
◈ API Testing — REST endpoint validation
◈ Integration — cross-service flows
◈ Regression — diff-based detection
◈ Negative — invalid input handling
◈ Boundary — min/max/null/overflow
3

Watch the live generation stream

After clicking Generate Tests, a WebSocket live log appears. Watch AURA:
• Load the knowledge graph (services, APIs, tech stack)
• Generate Playwright TypeScript spec files
• Generate pytest API test files
• Save artifacts to S3

💡 For the demo project, Bedrock generates tests based on the payment service: test_payment_create, test_payment_refund, test_boundary_max_amount, test_negative_invalid_currency, etc.

View results and artifacts

After generation: expand a test run row to see per-file pass/fail/skip breakdown.

5

Run Tests

Click Run Tests in the detail drawer. AURA executes the test suite and returns pass/fail/skip counts, duration, and coverage percentage per class.

Demo: AIOps — Live Monitoring

🎯
What to show AURA connects to live CloudWatch alarms and stored events. When an alert fires, AIOps correlates it with source code, service dependencies, and infrastructure to automatically explain the root cause — without anyone manually digging through logs.
1

Navigate to AI Ops

Click AI Ops in the sidebar. The live indicator shows whether CloudWatch is connected. KPI cards show active alarms, total alerts, agent runs.

💡 If no live CloudWatch alarms exist, the cards show "0 Active Alarms — All systems nominal". This is a good sign — show that it's truly live, not mocked.
2

Click "Trigger RCA"

This runs the 3-agent RCA pipeline:
1. AIOpsAgent — fetches CloudWatch alarms, correlates with service graph
2. RCAAgent — calls Bedrock Claude to generate root cause analysis
3. KnowledgeGraphAgent — stores RCA findings as triples in Neptune

3

Show the Source Correlation panel

The right sidebar shows: Alert → Service → Metric → Source chain for the top active alarm. This is the key differentiator — linking a monitoring alert directly to the responsible code and dependency.

4

Show Agent Pipelines tab

Switch to Agent Pipelines tab. Shows all orchestrator runs from DynamoDB with their agent chains and timestamps.

💡 This is the audit trail — every AI action is logged, traceable, and reviewable.

Section 8

FAQ & Objection Handling

Q: Does AURA send our source code to OpenAI or any external LLM provider?

A: No. AURA uses AWS Bedrock — Claude Sonnet is invoked inside your own AWS account and VPC. Your code never leaves your AWS environment. Bedrock's data processing agreement ensures no data is used for model training.

Q: How does this handle COBOL and mainframe code?

A: The Reverse Engineering Agent uses a COBOL parser to extract programs, paragraphs, sections, copybooks, and DB2 CALL statements. It maps these to the knowledge graph exactly like modern code. The Claims API demo project demonstrates this — 100% COBOL with IBM DB2 and VSAM dependencies fully mapped.

Q: What if our codebase has millions of lines?

A: Analysis is incremental and repository-level. We analyse per-repo, not the entire enterprise at once. For a 1M line Java monolith, we run CodeAnalysisAgent on it once and cache the knowledge graph — subsequent analyses only re-process changed files. Amazon Neptune scales horizontally for large graphs.

Q: Can the generated tests actually run against our systems?

A: Yes. The Playwright tests are standard .spec.ts files that run with npx playwright test. The pytest files run with standard pytest. They target your actual API endpoints. In production, we'd configure the CI/CD connector to trigger test execution on every PR.

Q: What's the production deployment model?

A: AURA deploys to AWS: React SPA → S3 + CloudFront, FastAPI backend → ECS Fargate behind ALB, Neptune cluster in the same VPC. Auth via Cognito. All traffic stays within your AWS account. Estimated cost: ~$800–1,200/month at moderate usage.
